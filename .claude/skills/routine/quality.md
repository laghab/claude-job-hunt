# Rank, tailor, outcome

## Rank (after collection, before applying)
1. Veto anything outside `profile.md` (location, experience minimum, pay floor, degree knockout, dealbreakers) or already in `applied.md` / `skipped.txt`.
2. Read the full posting. Score 0–2 each: role match, skill overlap (skills still being learned count half), level fit, pay/location fit, reply odds (fresh, < 100 applicants, real company, named recruiter).
3. **A** = total ≥ 8 with role match 2 → tailor + apply + outreach candidate. **B** = 5–7 → plain apply. **Skip** = < 5 or a veto → `skipped.txt` with the reason.
4. Write `ranked/YYYY-MM-DD.tsv` (grade, score, company, role, link, strengths, gaps).

## Tailor (A only)
1. Sources: the posting, the resume source, `answers.md`. Gaps stay gaps; no keyword stuffing.
2. Write a 3–4 sentence note naming the 2–3 resume items that match this posting.
3. Resume variant: copy the resume source and change presentation only (title line, skill order, which true summary lines lead). Check it's still one page and the text is selectable.
4. Show the note and the resume diff before using them. Upload the variant only where a site takes a per-application resume.

## Outcome (start of each run)
1. Update `applied.md` statuses from mail.
2. Append to `outcomes.md` per site, role family and grade: sent, viewed, replies, interviews.
3. After ~30 resolved applications, propose changes to these weights and to `profile.md`. Change nothing until the user agrees.
